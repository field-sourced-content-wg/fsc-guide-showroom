= FSC とは何か
:navtitle: FSC とは何か

== 学習目標

* FSC が解決する課題を理解する
* FSC の3つの主な目的を説明できる
* FSC のワークフロー全体像を把握する

== 背景と課題

デモ環境やハンズオンラボの構築には、以下のような課題があります。

[cols="1,2",options="header"]
|===
| 課題 | 具体例

| 手動作業が多い
| Operator のインストール、Custom Resource の作成、アプリケーションのデプロイを手動で実施

| 人的ミスが発生しやすい
| 手順の抜け漏れ、パラメータの設定ミス、順序の間違い

| 再現性が低い
| 同じ環境を別のクラスタで再構築する際に、手順書通りにいかない

| 共有が困難
| 作成者以外が環境を再現するためのドキュメントが不十分
|===

== FSC の定義

**Field Sourced Content (FSC)** は、OpenShift 上でデモ・ハンズオン環境を迅速かつ確実に構築するためのフレームワークです。

GitOps パターンを採用し、環境定義をコードとして Git リポジトリで管理します。

== 3つの目的

=== 再現性

誰が実行しても、同じ環境を何度でも構築できます。環境の定義が `values.yaml` として一元管理されているため、パラメータの差異が発生しません。

=== 自動化

ArgoCD を活用し、Git リポジトリの変更を自動的にクラスタへ反映します。手動での kubectl/oc コマンド実行は不要です。

=== 共有性

Git リポジトリを共有するだけで、他のメンバーも同じ環境を利用できます。引き継ぎ時のドキュメント作成コストを大幅に削減します。

== FSC のワークフロー全体像

FSC を使ったデモ環境構築は、以下の流れで進みます。

[cols="1,1,3",options="header"]
|===
| ステップ | 作業 | 説明

| 1
| テンプレートの準備
| 公式テンプレートリポジトリを fork/clone する

| 2
| values.yaml の編集
| 必要な Operator やコンポーネントを有効化する

| 3
| RHDP からオーダー
| Red Hat Demo Platform のカタログから環境を払い出す

| 4
| Showroom コンテンツ作成
| ハンズオンガイドを AsciiDoc 形式で作成する
|===

NOTE: 各ステップの詳細は「デモを作ってみよう」セクションでハンズオン形式で学びます。

== まとめ

* FSC はデモ環境構築の **再現性・自動化・共有性** を実現するフレームワーク
* GitOps パターンにより、環境定義をコードとして管理
* テンプレートから始めて、values.yaml を編集するだけで環境を構築可能
